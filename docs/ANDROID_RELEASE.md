# RoboLab-X Android release runbook

RoboLab-X is an Android-first Flutter application. The backend is a private service layer; users interact with the Android app.

## Android identity

- Package/application ID: `com.synapsex.robotics.robolab_x`
- Google Play subscription products:
  - `robolab_pro_monthly` — target display price ₹99/month
  - `robolab_pro_annual` — target display price ₹799/year

Prices shown by the production purchase sheet come from Google Play Console, not hard-coded client values.

## Google Sign-In

Create Google OAuth credentials for the Android package and its signing SHA fingerprints, plus a Web OAuth client used as the server client ID.

Set the Web OAuth client ID in two places:

1. Render backend secret/environment variable: `GOOGLE_CLIENT_ID`
2. GitHub Actions repository variable: `GOOGLE_SERVER_CLIENT_ID`

The Android app receives only the client ID. No client secret is embedded in the APK/AAB.

## Backend deployment

Deploy the repository with `render.yaml`. Required production secrets:

- `SESSION_SECRET` — generated by Render blueprint
- `GOOGLE_CLIENT_ID`
- `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` — service account JSON with appropriate Google Play Developer API access
- AI provider values only when external inference is enabled

The package name is configured as `ANDROID_PACKAGE_NAME=com.synapsex.robotics.robolab_x`.

## Google Play Billing

Create the two subscription products in Play Console with IDs matching the app. The app queries Google Play for product details and prices, sends `serverVerificationData` to `/api/v1/billing/google/verify`, and the backend verifies the subscription with Google Play before issuing a Pro session.

Do not unlock Pro from local purchase callbacks alone.

## GitHub Actions Android build

Set repository variables:

- `ROBOLAB_API_URL` — deployed backend HTTPS URL
- `GOOGLE_SERVER_CLIENT_ID` — Web OAuth client ID

Run **RoboLab-X Android Release** manually or push a tag matching `android-v*`. The workflow generates the Android platform when absent, runs analysis/tests, and outputs:

- release APK artifact
- release AAB artifact

For Google Play production publishing, configure Play App Signing and replace development signing with a protected release signing configuration. Never commit keystore passwords or private signing keys.

## Pre-release checks

- `/healthz` reports OK
- `/readyz` reports ready/degraded as expected for the configured AI mode
- Guest login succeeds
- Google login succeeds on a Play-signed/internal-test build
- Free project generation succeeds
- Pro beta/full specialist request succeeds
- Monthly and annual products appear from Google Play
- Purchase verification returns a Pro session
- Restore purchases works
- Offline project draft saves locally
- Flutter analyze/tests pass
- Release AAB installs through an internal Play test track
